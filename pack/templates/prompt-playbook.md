# Prompt Playbook — [PROJECT NAME]

## The four-part prompt
1. **Context** — what exists right now
2. **Goal** — what I want
3. **Constraints** — what must not change
4. **Success criteria** — how I'll judge it

## Habits
- One change per prompt (batches only for one KIND of change)
- Describe the observable problem, not a guessed solution
- Screenshots over paragraphs; point at files by name
- Explain before editing; plan before big changes
- The loop: look → describe → prompt one change → verify → commit

## Model roles (map to the current lineup — never hardcode version names)
Flagship + extended thinking → architecture, tricky debugging, security review
Workhorse (default) → features, design iteration, wiring, structured drafts
Efficient + low thinking → copy tweaks, alt text, renames, proofreading

## Escalation ladder
Start low → escalate on failure (not anxiety), same prompt → drop back down after
the hard part → three failed loops = stop, escalate, ask for diagnosis + plan.

## Conservation
Plan cheap first · fresh session per task · targeted edits over rewrites ·
context files carry standing instructions · max-everything is a spending setting.
